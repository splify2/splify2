# subscriptions — подписки: расписание, остаток трафика, названия

Официальный плагин splify2 (`splify2-core-plugins`). Данные подписок — файлы узлов, ссылки, остаток — остаются у каркаса
(ключ `subscription` выхода читает файл узлов, поэтому положить, перечитать и удалить подписку — каркас). Плагин делает
то, что над ними надстраивается: обновление по расписанию, остаток трафика по запросу и по расписанию, своё название.

Служит образцом: пользуется платформой **только через API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Интервал автообновления у каждой подписки (от получаса до трёх суток) | метод `sub_auto`, задача `update-subs` раз в десять минут |
| «Когда обновится» в списке подписок: поля `auto`, `auto_at`, `due` | хук `sub_fields` — каркас дописывает их в `sub_list` и `sub_info` |
| Остаток трафика: спросить у панели сейчас или по расписанию | метод `sub_quota`, настройка `quota_interval` |
| Своё название подписки | метод `sub_rename` |
| Расписание всех подписок одним ответом | новый метод `subs_schedule` |

Имена методов на объекте `splify2` прежние (`splify2.methods.alias`), интерфейс их не заметил. Без плагина `sub_auto`,
`sub_quota` и `sub_rename` отвечают «нужен плагин subscriptions», а в строках подписок нет полей расписания.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat`, `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Хук** `sub_fields` — поля расписания в ответах `sub_list` и `sub_info` (один вызов на ответ) | `hooks/sub-fields` |
| **Хук** `backup_sections` — расписание и настройки в архиве настроек | `hooks/backup` |
| **Хуки** `support_report`, `purge` | `hooks/support`, `hooks/purge` |
| **Задача** `update-subs` (`every: 10m`) вместо строки crontab | `bin/update-subs` |
| **Методы rpc** и псевдонимы | `bin/subs` |
| **Схема настроек** и значения через API (`s2_setting`) | `settings.schema.json` |
| **Службы хоста**: `sub list`, `sub info`, `sub refresh`, `sub quota`, `sub title`, `settings` | через `$SPLIFY2_HOST` |
| Рабочие каталоги: `STEER_PLUGIN_CONF` (расписание, отметки попыток) | `lib/base.sh` |

## Настройки

Хранятся в `conf/subscriptions/settings.json`, форма — по `settings.schema.json`:

| Ключ | Что |
|---|---|
| `min_interval` | наименьший интервал обновления, минут (по умолчанию 30) |
| `max_interval` | наибольший интервал, минут (по умолчанию 4320) |
| `quota_interval` | как часто спрашивать у панелей остаток трафика, не обновляя узлы; 0 — только по запросу |

Интервал, оказавшийся вне пределов после того, как их изменили, не действует (подписка не обновляется), пока человек не
задаст новый.

## Как решается «пора ли обновлять»

С последней попытки (отметка плагина или время файла узлов — что позже) прошёл весь интервал, и подписка заведена
ссылкой на панель (`kind: url`; вставленные руками ссылки обновлять нечем). Отметка ставится **до** похода наружу: при
мёртвой панели роутер стучится к ней раз в интервал, а не на каждом тике. Ручное «Обновить» меняет файл узлов, и срок
отодвигается сам. Туннель перечитывается только при изменившихся узлах — это решает `sub_refresh` каркаса.

## Переезд с 26.10

Интервал был полем uci (`splify2.main.sub_auto`, `splify2.sub_<имя>.auto`), отметка — файлом рядом с файлом узлов. При
установке пакета `uci-defaults` переносит их в `conf/subscriptions/` и снимает поля uci; строка crontab
`splify2-update-subs` снимается, задачу пишет `plugin_sync`. Архивы настроек формата 3 восстанавливаются: плагин
`backup` переводит поля `sub_auto` и `sub_<имя>.auto` в раздел `schedule` этого плагина.

## Раскладка

```
plugin.json              манифест
settings.schema.json     схема настроек
i18n/                    словари RU и EN (и i18n/core/ru.json — строки схемы для каркаса)
bin/subs                 методы rpc
bin/update-subs          задача: обновление по расписанию, остаток, чистка ушедших подписок
hooks/                   sub-fields, backup, support, purge
lib/base.sh              расписание, отметки времени, «пора ли»
```
