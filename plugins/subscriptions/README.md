# subscriptions — подписки: расписание, остаток трафика, названия

Официальный плагин splify2 (`splify2-core-plugins`), ставится вместе с пакетом. Данные подписок — файлы узлов, ссылки,
остаток — остаются у каркаса (ключ `subscription` выхода читает файл узлов, поэтому положить, перечитать и удалить
подписку — каркас). Плагин делает то, что над ними надстраивается: обновление по расписанию, остаток трафика по запросу и
по расписанию, своё название.

Служит образцом: пользуется платформой **только через API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Интервал автообновления у каждой подписки, в минутах; 0 — не обновлять | метод `sub_auto {name?, minutes}`, задача `update-subs` раз в десять минут |
| «Когда обновится» в списке подписок: поля `auto`, `auto_at`, `due` | хук `sub_fields` — каркас дописывает их в `sub_list` и `sub_info` |
| Остаток трафика: спросить у панели сейчас или по расписанию (узлы при этом не меняются) | метод `sub_quota {name?}`, настройка `quota_interval` |
| Своё название подписки; пустое — снять | метод `sub_rename {name?, title}` |
| Расписание всех подписок одним ответом | метод `subs_schedule` |

Без `name` методы берут первую подписку (`main`). Интервал принимается только у подписки, заведённой ссылкой на панель
(`kind: url`): у вставленных руками ссылок обновлять нечем. Имена методов на объекте `splify2` прежние
(`splify2.methods.alias`).

## Как решается «пора ли обновлять»

С последней попытки (отметка плагина или время файла узлов — что позже) прошёл весь интервал, и подписка заведена ссылкой
на панель. Отметка ставится **до** похода наружу: при мёртвой панели роутер стучится к ней раз в интервал, а не на каждом
тике. Заданный интервал отсчитывается от момента, когда его задали. Ручное «Обновить» меняет файл узлов, и срок
отодвигается сам. Туннель перечитывается только при изменившихся узлах — это решает `sub_refresh` каркаса. Задача
тикает раз в десять минут, поэтому интервал короче десяти минут на деле равен десяти.

Удалённая подписка уходит из расписания при следующем тике: заведённая заново под тем же именем чужой интервал не
наследует.

## Настройки

| Настройка в интерфейсе | Ключ | По умолчанию | Что |
|---|---|---|---|
| «Самый короткий интервал обновления, минут» | `min_interval` | 30 (от 5 до 4320) | чаще подписка не обновляется |
| «Самый длинный интервал обновления, минут» | `max_interval` | 4320 — трое суток (от 60 до 43200) | больший интервал не принимается |
| «Проверка остатка трафика, минут» | `quota_interval` | 0 (до 43200) | как часто спрашивать у панели остаток трафика, не обновляя узлы; 0 — только по запросу |

Интервал, оказавшийся вне пределов после того, как их изменили, не действует (подписка не обновляется), пока человек не
задаст новый.

Остаток трафика каждой подписки со ссылкой раз в сутки спрашивает и ночное обновление плагина `lists-catalog`.

## Где данные

Расписание (`schedule`, строки «имя минуты») и отметки последних попыток (`stamps/`) лежат в
`/etc/steer/plugins/conf/subscriptions/` рядом с настройками и переживают перезагрузку: после неё роутер не стучится ко
всем панелям разом. В архив настроек едут расписание (раздел `schedule`) и настройки (раздел `settings`). Каждый поход
к панели пишется в системный журнал с меткой `splify2-subs`.

При обновлении пакета с 26.10 прежние интервалы (поля uci `splify2.main.sub_auto`, `splify2.sub_<имя>.auto`) и отметки
переносятся сюда один раз, поля uci снимаются. Архивы настроек тех версий восстанавливаются: плагин `backup` переводит
эти поля в раздел `schedule`.

## Выключение и снятие

Плагин выключают и удаляют на вкладке «Плагины». Без него подписки по расписанию не обновляются (по кнопке — да, это
каркас), в строках подписок нет полей расписания, а `sub_auto`, `sub_quota` и `sub_rename` отвечают «Нужен плагин
subscriptions — поставьте его на вкладке «Плагины»». Удалённый плагин оставляет расписание и настройки в
`/etc/steer/plugins/conf/subscriptions/`, и после повторной установки интервалы на месте; убрать их вместе с плагином
можно на вкладке «Плагины» базового вида отметкой «Удалить и его настройки». Снятый плагин обновление пакета
splify2 не возвращает.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat` (`splify2-api ^1.0`), `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Хук** `sub_fields` — поля расписания в ответах `sub_list` и `sub_info` (один вызов на ответ) | `hooks/sub-fields` |
| **Хук** `backup_sections` — расписание и настройки в архиве настроек | `hooks/backup` |
| **Хуки** `support_report`, `purge` | `hooks/support`, `hooks/purge` |
| **Задача** `update-subs` (`every: 10m`) | `bin/update-subs` |
| **Методы rpc** и псевдонимы | `bin/subs` |
| **Схема настроек** и значения через API (`s2_setting`) | `settings.schema.json` |
| **Службы хоста**: `sub list`, `sub info`, `sub refresh`, `sub quota`, `sub title`, `settings` | через `$SPLIFY2_HOST` |
| Рабочий каталог `STEER_PLUGIN_CONF` (расписание, отметки попыток) | `lib/base.sh` |
