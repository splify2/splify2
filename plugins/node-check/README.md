# node-check — проверка узлов и выходов с роутера

Официальный плагин splify2 (`splify2-core-plugins`), ставится вместе с пакетом. Перебор узлов подписки, замер и страна
выхода делаются **на роутере**, а не в браузере: закрыл вкладку — перебор идёт, результат ждёт. Пользуется платформой
**только через API** ([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md));
`s2p lint --official` и стенд `tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или
функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Страна и адрес, где выходит выход; запомненный замер, обновление в фоне | метод `outbound_geo` (прежнее имя): без `fresh` отвечает из памяти и в сеть не ходит, устаревший замер обновляет в фоне; с `fresh` меряет сразу |
| Перебор всех узлов подписки (VLESS, hysteria2, прокси), не больше `parallel` сразу | методы `nodes_check` (запуск в фоне, один перебор на подписку), `nodes_result` (ход и итог), `nodes_cancel` |
| Лучший узел | метод `nodes_best` — самый быстрый из ответивших (протокол, номер, имя, мс) и закончен ли перебор |
| Перебор по расписанию | задача `check-nodes` раз в десять минут, если задана настройка `interval` (по умолчанию 0 — выключено); только при включённом автозапуске ядра |

Замер страны выхода, который снят до пересоздания устройства выхода (ядро меняет его при смене узла), не отдаётся вовсе:
плагин сверяет номер устройства (`probe ident`).

## Как перебор устроен

1. По имени подписки (или пути к её файлу узлов) плагин берёт у хоста файл узлов (`splify2-host sub list`); подписка
   должна быть уже скачана.
2. Узлы спрашиваются у трёх клиентов ядра (`call vless_nodes|hysteria2_nodes|proxy_nodes`); исключённые не входят. У
   прокси номера сквозные по всем пяти протоколам файла (trojan, shadowsocks, socks, http, vmess), поэтому проверка
   спрашивает именно их.
3. Каждый узел проверяется методом своего протокола (`call …_probe`): VLESS меряет ответ через туннель (`ttfb_ms`),
   hysteria2 и прокси — рукопожатие (`handshake_ms`). Одновременно не больше `parallel`: замер должен мерить узел, а не
   собственную очередь роутера.
4. Итог — `nodes_result`: `state` (`running`, `done`, `stopped`, `none`), `total`, `done`, `ok_count`, `best`, первая
   причина отказа `why` и узлы с исходом.

По расписанию подписки перебираются по одной; подписка, перебор которой идёт или был недавно (моложе `interval`),
пропускается.

## Настройки

| Настройка в интерфейсе | Ключ | По умолчанию | Что |
|---|---|---|---|
| «Проверок одновременно» | `parallel` | 3 (от 1 до 8) | сколько узлов проверяется сразу |
| «Проверять все подписки раз в, минут» | `interval` | 0 (до 10080) | как часто роутер сам проверяет каждый узел каждой подписки; 0 — только по запросу; задача тикает раз в десять минут |
| «Страна выхода свежа, секунд» | `geo_ttl_s` | 900 (от 60 до 86400) | столько используется замер страны выхода; более старый обновляется в фоне |
| «Повторять замер страны не чаще, секунд» | `geo_retry_s` | 60 (от 10 до 3600) | выход, у которого страну измерить не удалось, пробуется заново не раньше этого срока |

## Где данные

Замеры страны и итоги переборов — в рабочем каталоге плагина в памяти: узел мог смениться, и после перезагрузки роутера
старый замер вводил бы в заблуждение. Настройки — `/etc/steer/plugins/conf/node-check/settings.json`, они же едут в
архив настроек (раздел `settings`).

## Выключение и снятие

Плагин выключают и удаляют на вкладке «Плагины». Без него перебора узлов с роутера нет, а `outbound_geo` отвечает «Нужен
плагин node-check — поставьте его на вкладке «Плагины»». Отклик одного выхода (`outbound_probe`) и проверка DNS
(`dns_probe`) — методы каркаса и работают без плагина. Удалённый плагин оставляет настройки в
`/etc/steer/plugins/conf/node-check/`; убрать их вместе с плагином можно на вкладке «Плагины» базового вида
отметкой «Удалить и его настройки». Снятый плагин обновление пакета splify2 не возвращает.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat` (`splify2-api ^1.0`), `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Задача** `check-nodes` (`every: 10m`, `only_if: engine-enabled`) | `bin/check-nodes` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/` |
| **Методы rpc** и псевдоним старого имени `outbound_geo` | `bin/nodecheck` |
| **Схема настроек**, значения через API | `settings.schema.json` |
| **Службы хоста**: `call` (методы узлов и проверок), `sub list`, `probe geo\|ident`, `settings` | через `$SPLIFY2_HOST` |

События ядра плагину не нужны: перебор зовёт человек или задача, а устаревший замер страны распознаётся по номеру
устройства выхода, не по событию.

## Проверка

```sh
sh tests/nodecheckmatch.sh   # страна выхода, перебор, лучший узел, задача, архив
sh tests/hostmatch.sh        # службы call и probe
sh tests/pluginhygiene.sh    # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/node-check
```
