# node-check — проверка узлов и выходов с роутера

Официальный плагин splify2 (`splify2-core-plugins`). Перебор узлов подписки, замер и страна выхода живут **на роутере**, а
не в браузере: закрыл вкладку — перебор идёт, результат ждёт. До плагина перебор «проверить все» делала страница
(`ui/src/lib/subnodes.ts`, `probe.ts`): пока она открыта, ходят замеры, а результата для групп и автоподбора нет.
Пользуется платформой **только через API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Страна и адрес, где выходит выход; запомненный замер, обновление в фоне | метод `outbound_geo` (прежнее имя), кэш в памяти, пределы — настройки `geo_ttl_s`, `geo_retry_s` |
| Перебор всех узлов подписки (VLESS, hysteria2, прокси), не больше `parallel` сразу | методы `nodes_check` (запуск в фоне), `nodes_result` (ход и итог), `nodes_cancel` |
| Лучший узел | метод `nodes_best` — самый быстрый из ответивших (протокол, номер, имя, мс) |
| Перебор по расписанию | задача `check-nodes` раз в десять минут, если задана настройка `interval` (по умолчанию 0 — выключено) |

Измерения лежат в `STEER_PLUGIN_STATE` (память): узел мог смениться, и после перезагрузки роутера старый замер вводил бы
в заблуждение.

## Как перебор устроен

1. По имени подписки плагин берёт у хоста путь к её файлу узлов (`splify2-host sub list`).
2. Узлы спрашиваются у трёх клиентов ядра (`call vless_nodes|hysteria2_nodes|proxy_nodes`); исключённые не входят. У
   прокси номера сквозные по всем пяти протоколам файла, поэтому проверка спрашивает именно их.
3. Каждый узел проверяется методом своего протокола (`call …_probe`): VLESS меряет ответ через туннель (`ttfb_ms`),
   hysteria2 и прокси — рукопожатие (`handshake_ms`). Одновременно не больше `parallel` (по умолчанию 3): замер должен
   мерить узел, а не собственную очередь на единственном процессоре.
4. Итог — `nodes_result`: `state` (`running`, `done`, `stopped`, `none`), `total`, `done`, `ok_count`, `best`, первая
   причина отказа `why` и узлы с исходом.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat`, `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Задача** `check-nodes` (`every: 10m`, `only_if: engine-enabled`) | `bin/check-nodes` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/` |
| **Методы rpc** и псевдоним старого имени `outbound_geo` | `bin/nodecheck` |
| **Схема настроек**, значения через API | `settings.schema.json` |
| **Службы хоста**: `call` (методы узлов и проверок), `sub list`, `probe geo\|ident`, `settings` | через `$SPLIFY2_HOST` |

События ядра плагину не нужны: перебор зовёт человек или задача, а устаревший замер страны распознаётся по номеру
устройства выхода (`probe ident`), не по событию.

## Что не вошло

`outbound_probe` (отклик по одному выходу) и `dns_probe` остаются методами каркаса: это «проверка выхода» и «проверка
DNS», без которых нельзя выразить ядро. Плагин `group-check` считает приговор по членам групп поверх `outbound_probe`.

## Проверка

```sh
sh tests/nodecheckmatch.sh   # страна выхода, перебор, лучший узел, задача, архив
sh tests/hostmatch.sh        # службы call и probe
sh tests/pluginhygiene.sh    # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/node-check
```
