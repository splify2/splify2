# updater — версии и установка ядра и splify2

Официальный плагин splify2 (`splify2-core-plugins`). Показывает, какие версии ядра steer и самого splify2 есть в выпусках,
скачивает и ставит выбранную, помнит итог проверки «вышло ли новее». Пользуется платформой **только через API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Версии ядра и их названия, предварительная | метод `steer_versions` (прежнее имя) |
| Версии splify2 и установленная | метод `splify2_versions` |
| Скачать и поставить ядро: проверки до сети, суммы, зеркала, место на флеше, протоколы-плагины, автозапуск, перезапуск | метод `steer_install` |
| Скачать и поставить splify2 (пакет noarch, перезапуск rpcd) | метод `splify2_install` |
| Вышло ли новее, чем стоит; канал `stable` или `prerelease` | методы `update_status`, `update_check`, задача `check-updates` раз в шесть часов (настройка `check`, по умолчанию выключена) |

Имена методов на объекте `splify2` прежние (`splify2.methods.alias`), интерфейс их не заметил.

## Что осталось в каркасе (решение по О-2)

Решение О-2 не принято, поэтому в каркасе остаётся **минимум**, чтобы обновиться можно было и без плагина, и с ним, сломанным:
метод `engine` отдаёт объект `update` — `url` (страница выпусков) и `command` (команда установщика, он же обновляет), а
интерфейс показывает их там, где плагина нет. Всё остальное — выбор версии, скачивание, установка — плагин. Плагин **не**
защищён от снятия: на этом решении стоит и формулировка «минимум в каркасе»; если владелец решит иначе (защищённый и не
снимаемый плагин), в каркас достаточно добавить метку в таблицу `final` — код плагина не меняется.

Что каркас делает по-прежнему сам, потому что это его платформа, а не политика обновления: перечень выпусков с запасными
источниками (`version.json` с трёх адресов, `api.github.com`, `VERSION` ветки `dist`), скачивание со суммой и зеркалами, менеджер
пакетов (apk, opkg) с разрешением конфликта по имени, довод ядра после установки. Плагин получает всё это службами хоста.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat`, `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Задача** `check-updates` (`every: 6h`) | `bin/check-updates` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/` |
| **Методы rpc** и псевдонимы старых имён | `bin/updater` |
| **Схема настроек**, значения через API | `settings.schema.json` |
| **Службы хоста**: `release versions\|fetch`, `pkg info\|install`, `engine`, `engine modules\|settle`, `settings` | через `$SPLIFY2_HOST` |

## Настройки

| Ключ | Что |
|---|---|
| `check` | раз в шесть часов спрашивать у перечня выпусков, что вышло (по умолчанию выключено) |
| `channel` | `stable` — новым считается только законченный выпуск; `prerelease` — и текущая предварительная |

## Проверка

```sh
sh tests/updatermatch.sh     # проверка выпусков, канал, итог, задача, архив
sh tests/rpcdmatch.sh        # установка и версии сквозь плагин: суммы, зеркала, конфликты, место, откаты
sh tests/hostmatch.sh        # службы release, pkg, engine
sh tests/pluginhygiene.sh    # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/updater
```
