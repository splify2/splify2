# updater — версии и установка ядра и splify2

Официальный плагин splify2 (`splify2-core-plugins`), ставится вместе с пакетом. Показывает, какие версии ядра steer и
самого splify2 есть в выпусках, скачивает и ставит выбранную, помнит итог проверки «вышло ли новее». Пользуется
платформой **только через API** ([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md));
`s2p lint --official` и стенд `tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или
функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Версии ядра в выпусках, их названия и текущая предварительная | метод `steer_versions` |
| Версии splify2 в выпусках и установленная | метод `splify2_versions` |
| Скачать и поставить ядро (`steer-core`), довести нужные спеке протоколы-плагины ядра, включить автозапуск, перезапустить службу | метод `steer_install {version, modules?}` |
| Скачать и поставить пакет splify2 и перезапустить rpcd | метод `splify2_install {version}` |
| Вышло ли новее, чем стоит; канал `stable` или `prerelease` | методы `update_status`, `update_check`; задача `check-updates` раз в шесть часов (если включена настройка `check`) |

Имена `steer_versions`, `splify2_versions`, `steer_install` и `splify2_install` на объекте `splify2` те же, что у
каркаса (`splify2.methods.alias`); `update_status` и `update_check` — новые имена от плагина.

## Установка ядра

1. До сети: ядро не занято коннектором (podkop, forkop), версия — только цифры и точки и не старше 2.1.0 (младшей версии
   ядра, с которой работает splify2), архитектура роутера определена, имена просимых протоколов известны.
2. Файл `steer-core-<версия>-1_<архитектура>.<apk|ipk>` скачивается из выпуска ядра со сверкой суммы и запасными
   адресами; место на флеше проверяется до менеджера пакетов.
3. После установки ядро ставит протоколы-плагины, которые нужны спеке и которые просили (`modules`), затем включается
   автозапуск, спека переводится в `spec.yaml`, служба перезапускается, если спека есть. Отказ при доводе протоколов
   установку не отменяет: о нём говорит поле `ensure_error`.

Прежних пакетов `steer_install` не снимает. `splify2_install` ставит пакет `splify2` (выпуски до переименования — пакет
`luci-app-splify2`); если менеджер пакетов отказывает из-за конфликта с `luci-app-splify2` и называет его, этот пакет
снимается и установка повторяется (поле `removed` ответа). После установки страницу надо перезагрузить.

## Настройки

| Настройка в интерфейсе | Ключ | По умолчанию | Что |
|---|---|---|---|
| «Проверять новые версии само» | `check` | выключено | раз в шесть часов спрашивать у перечня выпусков, какие версии ядра и splify2 вышли, и запоминать итог; иначе — только по запросу (`update_check`) |
| «Канал выпусков» | `channel` | `stable` | `stable` — новыми считаются только законченные выпуски; `prerelease` — и текущая предварительная, если она новее |

Когда проверка находит новую версию, в системный журнал пишется строка с меткой `splify2-updater`.

## Где данные

Итог последней проверки — в рабочем каталоге плагина в памяти, после перезагрузки его нет. Настройки —
`/etc/steer/plugins/conf/updater/settings.json`, они же едут в архив настроек (раздел `settings`).

## Выключение и снятие

Плагин выключают и удаляют на вкладке «Плагины». Без него методы версий и установки отвечают «Нужен плагин updater —
поставьте его на вкладке «Плагины»». Обновиться можно и без плагина: метод каркаса `engine` отдаёт объект `update` —
страницу выпусков (`url`) и команду установщика (`command`). Удалённый плагин оставляет настройки в
`/etc/steer/plugins/conf/updater/`; убрать их вместе с плагином можно на вкладке «Плагины» базового вида отметкой
«Удалить и его настройки». Снятый плагин обновление пакета splify2 не возвращает.

Перечень выпусков, скачивание со сверкой суммы и менеджер пакетов (apk, opkg) — службы каркаса: перечень берётся из
`version.json` выпусков (raw.githubusercontent.com, jsDelivr, splify2.github.io), затем у `api.github.com`, последним —
из файла `VERSION` ветки `dist`.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat` (`splify2-api ^1.0`), `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Задача** `check-updates` (`every: 6h`) | `bin/check-updates` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/` |
| **Методы rpc** и псевдонимы | `bin/updater` |
| **Схема настроек**, значения через API | `settings.schema.json` |
| **Службы хоста**: `release versions\|fetch`, `pkg info\|install`, `engine`, `engine modules\|settle`, `settings` | через `$SPLIFY2_HOST` |
| Рабочий каталог `STEER_PLUGIN_STATE` (итог проверки, скачанный файл) | `lib/base.sh` |

## Проверка

```sh
sh tests/updatermatch.sh     # проверка выпусков, канал, итог, задача, архив
sh tests/rpcdmatch.sh        # установка и версии сквозь плагин: суммы, зеркала, конфликты, место, откаты
sh tests/hostmatch.sh        # службы release, pkg, engine
sh tests/pluginhygiene.sh    # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/updater
```
