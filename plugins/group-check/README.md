# group-check — проверка групп выходов

Официальный плагин splify2 (`splify2-core-plugins`). Ядро выбирает член группы само (`pick: latency` — самый быстрый с
допуском, `order` — первый живой), но не говорит человеку, **кто из членов плохой и давно ли**. Плагин добавляет к ядру то,
чего в нём нет: приговор по каждому члену, историю отказов и подсказку «член мёртв». Пользуется платформой **только через
API** ([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что считать «проверкой» (решение по О-14)

В UI этого не было вовсе, поэтому это не перенос, а новая логика поверх ядра, и она намеренно небольшая:

- **Проверка** — проба одного члена группы методом каркаса `outbound_probe` (ядро меряет туннели сами, обычное устройство —
  ping через него). Группа, вложенная в группу, и выход без устройства не пробуются: приговор `unknown`, это не отказ.
- **Приговор** по серии проб подряд: `alive` — ответил; `unstable` — отказал, но меньше `dead_after` раз подряд; `dead` —
  отказал `dead_after` раз подряд (по умолчанию 3); `unknown` — проверять нечем.
- **Подсказка** — запись `{code: member_dead, group, member}` для каждого мёртвого члена: интерфейс говорит словами, плагин
  отдаёт машинное слово.
- **История** — перемены приговоров и события ядра `switched` (с членом и причиной) и `failed` по группам спеки; последние
  `history` записей (по умолчанию 200) на группу.

## Что делает

| Что | Как |
|---|---|
| Проба всех членов всех групп спеки по расписанию | задача `check-groups` раз в пять минут, настройки `enabled`, `interval` |
| Приговор, отклик, серия отказов, «с какого времени» | метод `group_status {group?}` |
| Проверить сейчас | метод `group_check {group?}` |
| История | метод `group_history {group, limit?}` |
| Переключения группы и отказы выходов | события ядра `switched`, `failed` |

Состояние и история лежат в `STEER_PLUGIN_STATE` (память): запись на флеш при каждой пробе незачем, а после перезагрузки
члены и так могли смениться.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat`, `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Задача** `check-groups` (`every: 5m`, `only_if: engine-enabled`) | `bin/check-groups` |
| **События** `switched`, `failed` | `hooks/event` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/` |
| **Методы rpc** (новые имена на объекте `splify2`) | `bin/groupcheck` |
| **Схема настроек**, значения через API | `settings.schema.json` |
| **Службы хоста**: `spec get`, `call outbound_probe`, `settings` | через `$SPLIFY2_HOST` |

## Настройки

| Ключ | Что |
|---|---|
| `enabled` | проверять по расписанию (по умолчанию да); выключено — только по запросу |
| `interval` | интервал проб, минут (по умолчанию 5; тик расписания — пять минут) |
| `dead_after` | сколько отказов подряд делают члена мёртвым (по умолчанию 3) |
| `history` | сколько записей истории хранить на группу (по умолчанию 200) |
