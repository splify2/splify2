# group-check — проверка групп выходов

Официальный плагин splify2 (`splify2-core-plugins`), ставится вместе с пакетом. Ядро выбирает член группы само
(`pick: latency` — самый быстрый с допуском, `order` — первый живой), но не говорит человеку, **кто из членов плохой и
давно ли**. Плагин добавляет к ядру то, чего в нём нет: приговор по каждому члену, историю отказов и подсказку «член
мёртв». Выбор члена плагин не меняет — выбирает по-прежнему ядро. Пользуется платформой **только через API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что считается проверкой

- **Проба** — один замер члена группы методом каркаса `outbound_probe`: туннели VLESS, hysteria2 и прокси меряет ядро
  через сам туннель, обычное устройство — ping через него. Член без своего устройства (например, вложенная группа) и
  член, которого пробой не достать, получают приговор `unknown` — это не отказ.
- **Приговор** по серии проб подряд: `alive` — ответил; `unstable` — отказал, но меньше `dead_after` раз подряд; `dead` —
  отказал `dead_after` раз подряд; `unknown` — проверять нечем.
- **Подсказка** — запись `{code: member_dead, group, member}` для каждого мёртвого члена: машинное слово, а не текст.
- **История** — перемены приговоров и события ядра `switched` (с членом и причиной) и `failed` по группам спеки; хранится
  последние `history` записей на группу.

## Что делает

| Что | Как |
|---|---|
| Проба всех членов всех групп спеки по расписанию | задача `check-groups`: тик раз в пять минут, группа пробуется, когда с её прошлой проверки прошёл `interval`; только при включённом автозапуске ядра |
| Приговор, отклик, серия отказов, «с какого времени», подсказки | метод `group_status {group?}` |
| Проверить сейчас, не дожидаясь расписания | метод `group_check {group?}` |
| История | метод `group_history {group, limit?}` (по умолчанию последние 50 записей) |
| Переключения группы и отказы выходов | события ядра `switched`, `failed` |

## Настройки

| Настройка в интерфейсе | Ключ | По умолчанию | Что |
|---|---|---|---|
| «Проверять группы по расписанию» | `enabled` | включено | выключено — только по запросу (`group_check`) |
| «Проверять раз в, минут» | `interval` | 5 (от 5 до 1440) | как часто пробуются члены; расписание тикает раз в пять минут |
| «Член мёртв после отказов подряд» | `dead_after` | 3 (от 1 до 20) | столько отказов подряд делают члена мёртвым, меньше — нестабильным |
| «Записей истории на группу» | `history` | 200 (от 10 до 5000) | сколько последних перемен приговора и событий ядра хранить |

## Где данные

Приговоры и история — в рабочем каталоге плагина в памяти: запись на флеш при каждой пробе незачем, а после перезагрузки
члены и так могли смениться; после перезагрузки история пуста. Настройки — `/etc/steer/plugins/conf/group-check/settings.json`,
они же едут в архив настроек (раздел `settings`).

## Выключение и снятие

Плагин выключают и удаляют на вкладке «Плагины». Выключенный не пробует членов и не пишет историю, его методы недоступны;
на выбор члена ядром это не влияет. Удалённый оставляет настройки в `/etc/steer/plugins/conf/group-check/`; убрать их
вместе с плагином можно на вкладке «Плагины» базового вида отметкой «Удалить и его настройки». Снятый плагин
обновление пакета splify2 не возвращает.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat` (`splify2-api ^1.0`), `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Задача** `check-groups` (`every: 5m`, `only_if: engine-enabled`) | `bin/check-groups` |
| **События** `switched`, `failed` | `hooks/event` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/` |
| **Методы rpc** (новые имена на объекте `splify2`) | `bin/groupcheck` |
| **Схема настроек**, значения через API | `settings.schema.json` |
| **Службы хоста**: `spec get`, `call outbound_probe`, `settings` | через `$SPLIFY2_HOST` |

## Проверка

```sh
sh tests/groupcheckmatch.sh   # приговоры, подсказки, история, события, расписание, архив
sh tests/pluginhygiene.sh     # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/group-check
```
