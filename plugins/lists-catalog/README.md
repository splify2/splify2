# lists-catalog — каталог списков

Официальный плагин splify2 (`splify2-core-plugins`), ставится вместе с пакетом: каталог списков сервисов и сайтов,
загрузка списков, свои списки, обновление раз в сутки. Служит образцом: он пользуется платформой **через её API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)) — `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Каталог списков и второй издатель (`itdoginfo/allow-domains`, наборы `.srs` релиза с закреплённым тегом) | методы `lists`, `allow_domains`, `list_fetch`, `list_remove`, `local_lists`, `list_peek` (первые 300 записей списка) |
| Свои списки: текстом, ссылкой, файлом, набором `.srs`; не больше 1 МБ на список, записи проходят проверку, отброшенные называются числом | `list_put`, `list_srs_put`, `list_custom`, `list_get` |
| Обновление раз в сутки и по кнопке | задача `update-lists` и метод `lists_update` |
| Довоз списков, на которые ссылается спека, но которых нет на диске (ядро не принимает спеку с отсутствующим файлом) | хуки `pre_spec_set` и `pre_apply`: не скачавшийся список — предупреждение, а не отказ |
| Откуда брать каталог, как качать | `lists_source`, `lists_source_set` (настройка плагина), `fetch_mode`, `fetch_mode_set` (режим хоста) |

Имена методов на объекте `splify2` прежние (`splify2.methods.alias`).

## Обновление раз в сутки

- Время — 05:xx по часам роутера; минута выбирается случайно один раз для роутера, чтобы роутеры не приходили к
  издателю в одну минуту. Только если спека есть.
- Обновляются **только списки, на которые ссылается спека**. Адресные подгоняются под свободную память роутера
  (`steer fit`). Срок одного скачивания — 120 с.
- Список, у которого было 100 записей и больше и который сократился **больше чем** в `list_shrink_factor` раз, не
  заменяется — остаётся прежняя копия. Пустой скачанный список не заменяет прежний никогда, даже при пороге 0.
- Изменилось что-то — применение (то же, что кнопка «Применить»). Ядро отвергло обновлённые списки — возвращаются
  прежние копии и применяются снова. Ядро выключено человеком (автозапуск снят) — списки обновляются на диске, правила не
  применяются.
- Тег второго издателя ночное обновление не двигает: файлы того же тега повторно не скачиваются.
- Заодно прогон спрашивает у панели каждой подписки со ссылкой остаток трафика (метод `sub_quota` плагина
  `subscriptions`).

Отчёт о прогоне — в системном журнале с меткой `lists-catalog`.

## Настройки

| Настройка в интерфейсе | Ключ | По умолчанию | Что |
|---|---|---|---|
| «Каталог» | `manifest_url` | `https://github.com/splify2/splify2-lists/releases/latest/download/lists.json` | адрес файла каталога (`http://` или `https://`); пусто — каталог splify2-lists. Смена адреса уже скачанные списки не трогает; при смене из панели списков (`lists_source_set`) перечень перечитывается заново |
| «Порог сокращения списка» | `list_shrink_factor` | 4 (0 и больше) | при обновлении список, сократившийся больше чем во столько раз, не заменяется; 0 — без порога |
| «Версия списков второго издателя» | `allow_domains_tag` | пусто | тег релиза списков allow-domains; пусто — тег, закреплённый в плагине (`2026-09-14_15-11`). `latest` и значение не по форме тега не принимаются — берётся закреплённый, с предупреждением в журнале |

Режим «качать через туннель» — не настройка плагина: он общий для всего, что скачивает каркас (списки, пакеты ядра,
подписки), поэтому им владеет хост (`splify2-host fetch-mode`): `always` или `off`.

## Где данные

- Списки — в каталоге списков ядра `/etc/steer/lists`, свои — в его подкаталоге `custom`.
- Настройки, кэш каталога (`manifest.json`) и отметки версий второго издателя — `/etc/steer/plugins/conf/lists-catalog/`:
  каталог, скачанный раз, переживает перезагрузку.
- Замок прогона и временные файлы — в рабочем каталоге плагина в памяти.

## Свои списки в архиве настроек

Архив настроек (плагин `backup`) просит плагин отдать разделы: `list_domains_<имя>`, `list_prefixes_<имя>` на каждый свой
список и `settings`. В имени раздела допустимы только буквы, цифры и подчёркивание, поэтому в имени списка `_` удваивается
(`__`), а `-` пишется `_d`: список `mine-a` едет разделом `list_prefixes_mine_da`. Кодировка однозначна. При
восстановлении списки проходят **ту же** проверку и тот же предел размера, что и при загрузке своего списка.

## Выключение и снятие

Плагин выключают и удаляют на вкладке «Плагины». Без него методы каталога отвечают «Нужен плагин lists-catalog —
поставьте его на вкладке «Плагины»», суточного обновления и довоза недостающих списков нет. Скачанные и свои списки
остаются в `/etc/steer/lists`, и правила, которые на них ссылаются, продолжают работать с последней копией. Удалённый
плагин оставляет `/etc/steer/plugins/conf/lists-catalog/`; убрать его вместе с плагином можно на вкладке «Плагины»
базового вида отметкой «Удалить и его настройки». Снятый плагин обновление пакета splify2 не возвращает.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat` (`splify2-api ^1.0`), `permissions` (`splify2.hooks`, `http`, `fs:/etc/steer/lists`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Хуки** `pre_spec_set` и `pre_apply` (режим `warn`) — довезти списки, на которые ссылается спека | `hooks/ensure-lists`, `lib/fetch-missing.sh` |
| **Хук** `backup_sections` — свои списки и настройки в архиве настроек (операции `export`, `check`, `restore`) | `hooks/backup` |
| **Хуки** `support_report` и `purge` | `hooks/support`, `hooks/purge` |
| **Задача** `update-lists` (`cron: M 5 * * *`, `jitter: random-minute`, `only_if: spec-present`) | `bin/update-lists` |
| **Методы rpc** и псевдонимы старых имён | `bin/lists`, `lib/methods.sh` |
| **Схема настроек** и значения через API (`s2_setting`, `splify2-host settings`) | `settings.schema.json` |
| **Словари** `i18n`: `plugin.name`, `plugin.description` (RU, EN), строки схемы настроек (`i18n/core/ru.json`) | `i18n/` |
| **Службы хоста**: `fetch`, `fetch-mode`, `paths`, `spec get\|uses`, `apply`, `engine`, `settings` | вызываются через `$SPLIFY2_HOST` |
| **Ресурсы ядра**: каталог списков и программа ядра (`srs-read`, `fit`) — их называет хост (`paths`) | `lib/base.sh` (`lists_init`) |
| Рабочие каталоги: `STEER_PLUGIN_CONF` (кэш каталога, отметки версий), `STEER_PLUGIN_STATE` (замок, временные файлы) | `lib/base.sh` |

Слот интерфейса плагину не нужен: вкладку каталога рисует панель через те же методы, форма настроек строится по схеме.

## Раскладка

```
plugin.json              манифест
settings.schema.json     схема настроек
i18n/                    словари RU и EN (и i18n/core/ru.json — строки схемы)
bin/lists                методы rpc (диспетчер по первому аргументу)
bin/update-lists         суточное обновление (задача и метод lists_update)
hooks/                   ensure-lists, backup, support, purge
lib/base.sh              общее: пути от хоста, скачивание, разбор каталога, свои списки
lib/methods.sh           тела методов
lib/fetch-missing.sh     довоз списков спеки (хук)
lib/allow-domains.sh     описание второго издателя и разбор его наборов
```
