# backup — архив настроек

Официальный плагин splify2 (`splify2-core-plugins`), ставится вместе с пакетом: выгрузка настроек роутера в файл и
восстановление из него. Служит образцом: он пользуется платформой **только через её API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

Плагин знает **формат архива** и умеет передавать его по кускам (по 16 КБ). Всё остальное берёт у платформы:

| Что едет в архив | Кто знает, что это и как проверять |
|---|---|
| спека, подписки, выбор у групп, ключи туннелей xsteer, файлы своих туннелей WireGuard и AmneziaWG (выходы `kind: awg`), поля uci каркаса | хост: `splify2-host state export\|check\|import` |
| свои списки, настройки и данные других плагинов | сами плагины: хук `backup_sections` (операции `export`, `check`, `restore`) |

Остатка трафика подписок в архиве нет: это не настройка, а последний ответ панели. Своих настроек плагин `backup` в архив
не кладёт.

Методы на объекте `splify2` прежние: `backup_get`, `backup_put` (в плагине — `get` и `put`). Права `write`, а не `read`:
в архиве приватные ключи туннелей и ссылки узлов. Об этом предупреждает и шапка самого архива: файл — то же, что пароль от
всех подключений, его не выкладывают в чат поддержки и не хранят в общей папке.

## Формат

Строчный, с разделами в квадратных скобках; содержимое дословное. Первая строка — `splify2-backup N`, строки `#` —
комментарии (кроме разделов туннелей, которые едут дословно), разделы: `[spec]`, `[sub]`, `[sub имя]`, `[select]`,
`[xsteer имя]`, `[awg имя]`, `[plugin <id> <имя>]`, `[options]`. Версия формата — по набору разделов: 3 — разделы
каркаса, 4 — плюс разделы плагинов (строки раздела плагина едут с отступом в один пробел), 5 — плюс файлы своих туннелей
`[awg имя]`. Разбор принимает любую версию не новее своей (до 5); более новую, неизвестный или повторённый раздел
отвергает целиком.

Архивы, собранные до выноса каталога списков и расписания подписок в плагины, восстанавливаются: разделы `[list …]` и
поля `manifest_url`, `list_shrink_factor` из `[options]` переезжают к плагину `lists-catalog`, а интервалы
автообновления подписок — в раздел `schedule` плагина `subscriptions`.

## Порядок восстановления

1. Присланный файл копится по кускам с пределом на общий размер, проверяется на двоичные байты и разбирается строгим
   разборщиком по разделам (недоверенный ввод: размер, управляющие байты, имена).
2. **Проверка всего, ничего не записывая:** настройки каркаса — `state check`, данные плагинов — операция `check`. Отказ
   любой проверки отменяет восстановление целиком.
3. Запись: сначала разделы плагинов (`restore`) — спека из архива ссылается на файлы, которые они кладут, — затем настройки
   каркаса (`state import`: подписки и ключи раньше спеки, спека проверяется ядром). Раздел плагина, которого нет на
   роутере, не восстанавливается — об этом предупреждение, остальное восстанавливается.
4. Сам плагин ничего не применяет: восстановленное — сохранённое и не применённое. С включённым плагином `autoapply`
   его применяет роутер: Andromeda после восстановления просит применить сразу, а без открытой страницы его применит
   проверка неприменённого (раз в пять минут). Без `autoapply` применяет Andromeda из браузера или кнопка «Применить»
   базового вида.

## Настройки

| Настройка в интерфейсе | Ключ | По умолчанию | Что |
|---|---|---|---|
| «Предел размера архива, КБ» | `max_archive_kb` | 2048 (от 256 до 65536) | архив собирается и принимается в памяти; больший отклоняется с названием размера — и при выгрузке, и при восстановлении |

## Где данные

Своих данных у плагина нет. Архив собирается и разбирается в закрытом рабочем каталоге плагина в памяти и удаляется после
выгрузки или восстановления. Настройка — `/etc/steer/plugins/conf/backup/settings.json`.

## Выключение и снятие

Плагин выключают и удаляют на вкладке «Плагины». Без него выгрузки и восстановления нет: `backup_get` и `backup_put`
отвечают «Нужен плагин backup — поставьте его на вкладке «Плагины»». Снятый плагин обновление пакета splify2 не
возвращает.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat` (`splify2-api ^1.0`), `i18n`, `rpc`, `splify2` (псевдонимы, схема настроек) | `plugin.json` |
| **Методы rpc** и псевдонимы старых имён | `bin/backup`, `lib/archive.sh` |
| **Службы хоста**: `state check\|export\|import` (настройки каркаса), `hook backup_sections` (разделы плагинов) | `$SPLIFY2_HOST` |
| **Схема настроек** и значение через API (`s2_setting max_archive_kb`) | `settings.schema.json` |
| **Словари** `i18n`: `plugin.name`, `plugin.description` (RU, EN), строки схемы (`i18n/core/ru.json`) | `i18n/` |
| Рабочий каталог `STEER_PLUGIN_STATE` (память, закрытый 0700): сюда собирается и принимается архив | `lib/archive.sh` |

Хуков, задач и событий у плагина нет: архив собирается и восстанавливается по запросу человека. Слот интерфейса не нужен:
карточку архива рисует панель.

## Проверка

```sh
sh tests/rpcdmatch.sh       # разбор присланного файла, отказы, круг выгрузка → восстановление
sh tests/hostmatch.sh       # службы хоста, на которых стоит плагин
sh tests/pluginhygiene.sh   # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/backup
```
