# autoapply — применение на роутере

Официальный плагин splify2 (`splify2-core-plugins`), ставится вместе с пакетом. Сохранённые настройки применяет **сам
роутер, через короткую паузу после последней правки, даже когда страница закрыта**. Панель Andromeda при включённом
плагине сама ничего не применяет: она записывает правку, показывает «Применение…», пока роутер занят, и сверяется с ним
по `autoapply_status`. Пользуется платформой **только через API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Спека записана — применить через паузу, подряд идущие правки одним применением | хук `post_spec_set` ставит метку и запускает отложенное применение (`bin/apply-later`): применяет только последний ожидающий |
| Сохранённое и не применённое (другое окно, ядро было недоступно, перезагрузка в паузе) | задача `sweep` раз в пять минут, если спека есть |
| Применять нечего (спека равна снимку применённого) — роутер не трогается | служба хоста `spec get --applied` |
| Отвергнутое ядром не повторяется, пока спека не изменится; «не состоялось» (ядро занято коннектором, применение остановил хук плагина) повторяется | отпечаток отвергнутой спеки, исход службы `apply` (коды 1 и 3) |
| Правка во время применения | её хук ставит новое ожидание; применение идёт следом, под тем же замком каркаса, что и запись спеки |
| Состояние для интерфейса: `applying` (роутер применяет), `pending` (ждёт паузу), `rejected` (ядро отвергло эту спеку), `unapplied` (сохранено и не применено), `idle` (всё применено) | `autoapply_status`, поле `state`; метка «применяется» ставится до снятия метки ожидания, брошенная (процесса нет) не считается |
| Применить сейчас, не дожидаясь исхода (открыли страницу с неприменённым, конец пачки правок) | `autoapply_kick` — ответ сразу, исход в `autoapply_status`; при выключенной настройке `enabled` ничего не делает |
| Применить сейчас и дождаться исхода | `autoapply_now` — применяет и при выключенной настройке `enabled` |
| Отменить ожидающее применение | `autoapply_cancel` |
| Применили без плагина (кнопкой, другим путём) — забыть отвергнутое | событие ядра `applied` |

Применение — та же служба, что кнопка «Применить»: зоны фаервола, хуки плагинов, снимок применённого. Оно идёт под
замком каркаса, и второе применение той же спеки ничего не меняет.

## По умолчанию включено

С версии 1.1 записанное применяется на роутере без участия страницы, пока человек не выключил настройку «Применять
сохранённое само». Выключенная настройка, выключенный или снятый плагин ничего не меняют в каркасе — там «Применить»
остаётся явным действием, — а Andromeda в этом случае применяет сама, из браузера, через 0,8 с тишины после записи (пока
страница открыта).

## Настройки

| Настройка в интерфейсе | Ключ | По умолчанию | Что |
|---|---|---|---|
| «Применять сохранённое само» | `enabled` | включено | применять сохранённое на роутере; выключено — только явным действием |
| «Пауза после последней правки, секунд» | `pause_s` | 1 (от 1 до 3600) | правки в пределах паузы применяются одним применением |
| «Применять сохранённое и не применённое» | `sweep` | включено | раз в пять минут применять то, что сохранили и не применили; отвергнутое не повторяется, пока спека не изменится |

## Где данные

Настройки — `/etc/steer/plugins/conf/autoapply/settings.json`, они же едут в архив настроек (раздел `settings`). Метка
ожидания, исход последнего применения и отпечаток отвергнутой спеки — в рабочем каталоге плагина в памяти, после
перезагрузки их нет. Исход каждого применения пишется в системный журнал с меткой `splify2-autoapply`.

## Выключение и снятие

Плагин выключают и удаляют на вкладке «Плагины». У выключенного не работают хук, задача и методы, настройки остаются.
Удалённый оставляет настройки в `/etc/steer/plugins/conf/autoapply/`; убрать их вместе с плагином можно на вкладке
«Плагины» базового вида отметкой «Удалить и его настройки». В обоих случаях применяет Andromeda из браузера (см.
выше). Снятый плагин обновление пакета splify2 не возвращает.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat` (`splify2-api ^1.0`), `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Хук** `post_spec_set` (наблюдатель) | `hooks/spec-saved` |
| **Задача** `sweep` (`every: 5m`, `only_if: spec-present`) | `bin/sweep` |
| **События** `applied`, `failed` | `hooks/event` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/backup`, `hooks/support`, `hooks/purge` |
| **Методы rpc** и псевдонимы | `bin/autoapply` |
| **Схема настроек**, значения через `s2_setting` | `settings.schema.json` |
| **Службы хоста**: `spec get [--applied]`, `apply`, `settings` | через `$SPLIFY2_HOST` |
| Рабочий каталог `STEER_PLUGIN_STATE` (метка ожидания, исход, отпечаток отвергнутого) | `lib/base.sh` |

## Проверка

```sh
sh tests/autoapplymatch.sh   # хук, пауза, склейка правок, kick и состояние «применяется», sweep, события, методы, архив
sh tests/hostmatch.sh        # служба spec get --applied
sh tests/pluginhygiene.sh    # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/autoapply
```
