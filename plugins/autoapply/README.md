# autoapply — применение на роутере

Официальный плагин splify2 (`splify2-core-plugins`). Сохранённые настройки применяет **сам роутер, через короткую паузу
после последней правки, даже когда страница закрыта**. Интерфейс (Andromeda) при включённом плагине сам ничего не
применяет: он записывает правку, показывает «Применение…», пока роутер занят, и сверяется с ним по `autoapply_status`.
Пользуется платформой **только через API**
([splify2-api](https://github.com/splify2/plugin-sdk/blob/main/docs/splify2-api.md)); `s2p lint --official` и стенд
`tests/pluginhygiene.sh` отказывают плагину, который заглянет в файлы, переменные или функции каркаса.

## Что делает

| Что | Как |
|---|---|
| Спека записана — применить через паузу, подряд идущие правки одним применением | хук `post_spec_set` ставит метку и запускает отложенное применение (`bin/apply-later`): применяет только последний ожидающий |
| Сохранённое и не применённое (другое окно, ядро было недоступно, перезагрузка в паузе) | задача `sweep` раз в пять минут |
| Применять нечего (спека равна снимку применённого) — роутер не трогается | служба хоста `spec get --applied` |
| Отвергнутое ядром не повторяется, пока спека не изменится; «не состоялось» (ядро занято коннектором, остановил хук) повторяется | отпечаток отвергнутой спеки, исход службы `apply` (коды 1 и 3) |
| Правка во время применения | её хук ставит новое ожидание; применение идёт следом, под тем же замком каркаса, что и запись спеки |
| Состояние для интерфейса: `applying` (роутер применяет), `pending` (ждёт паузу), `rejected`, `unapplied`, `idle` | `autoapply_status`, поле `state`; метка «применяется» ставится до снятия метки ожидания, брошенная (процесса нет) не считается |
| Применить сейчас, не дожидаясь исхода (открыли страницу с неприменённым, конец пачки правок) | `autoapply_kick` — ответ сразу, исход в `autoapply_status` |
| Применить сейчас и дождаться исхода, отменить ожидающее | `autoapply_now`, `autoapply_cancel` |
| Применили без нас — забыть отвергнутое | событие ядра `applied` |

## По умолчанию включено

С версии 1.1 плагин включён, пока человек не выключил настройку `enabled`: записанное применяется на роутере без участия
страницы. Выключенный плагин ничего не меняет в поведении каркаса — «Применить» там явное действие, — а Andromeda в этом
случае применяет сама, из браузера, через 0,8 с тишины (`ui/src/lib/autoapply.ts`). Применение идемпотентно и идёт под
замком каркаса: второе применение той же спеки ничего не меняет.

## Какие точки API использует

| Точка API | Где |
|---|---|
| Манифест: `compat`, `permissions` (`splify2.hooks`), `i18n`, `rpc`, `splify2` | `plugin.json` |
| **Хук** `post_spec_set` (наблюдатель) | `hooks/spec-saved` |
| **Задача** `sweep` (`every: 5m`, `only_if: spec-present`) | `bin/sweep` |
| **События** `applied`, `failed` | `hooks/event` |
| **Хуки** `backup_sections`, `support_report`, `purge` | `hooks/backup`, `hooks/support`, `hooks/purge` |
| **Методы rpc** и псевдонимы | `bin/autoapply` |
| **Схема настроек**, значения через `s2_setting` | `settings.schema.json` |
| **Службы хоста**: `spec get [--applied]`, `apply`, `settings` | через `$SPLIFY2_HOST` |
| Рабочий каталог `STEER_PLUGIN_STATE` (метка ожидания, исход, отпечаток отвергнутого) | `lib/base.sh` |

## Настройки

| Ключ | Что |
|---|---|
| `enabled` | применять сохранённое на роутере (по умолчанию включено) |
| `pause_s` | пауза после последней правки, секунд (по умолчанию 1) |
| `sweep` | применять сохранённое и не применённое раз в несколько минут (по умолчанию да) |

## Проверка

```sh
sh tests/autoapplymatch.sh   # хук, пауза, склейка правок, kick и состояние «применяется», sweep, события, методы, архив
sh tests/hostmatch.sh        # служба spec get --applied
sh tests/pluginhygiene.sh    # граница API
sh /путь/к/plugin-sdk/tests/compat/run.sh plugins/autoapply
```
