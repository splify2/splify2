# @andromeda/ui — пакет

> Этот раздел — про пакет в репозитории; ниже, с «Andromeda — как строить с этой
> системой», идёт руководство самой дизайн-системы, как оно пришло из экспорта.

## Откуда взялся и что в нём восстановлено

Пакет жил вне git, на машине, где собиралась панель «Солнечный», и потерялся вместе с ней:
на сервере xcloud его не было никогда (9 сентября проверено — ни каталога, ни
`node_modules`), бандл панели туда привозился готовым. 24 сентября 2026 пакет собран заново
из экспорта дизайн-системы (архив `Andromeda.zip`: компоненты, объявления, токены, стили) и
того, чего в экспорте не было, восстановленного по собранному бандлу панели от 28 августа,
который работает в xcloud («Показатели»):

- `theme/ThemeProvider.tsx` — `ThemeProvider`, `useTheme`, `ThemeMode`, `ACCENTS`, `Accent`.
  Поведение взято из бандла один в один: ключи `<prefix>-theme` / `<prefix>-accent`,
  по умолчанию светлая тема и индиго, `data-theme="dark"` и класс `dark` на `<html>`,
  `data-accent` (у индиго атрибута нет).
- `index.ts` и `types/index.d.ts` — точка входа; состав совпадает с `_ds_manifest.json`
  экспорта (37 компонентов).
- `package.json` — имя, версия 0.2.0 и peer-зависимости из `package-lock.json` панели.
  Инструменты сборки оригинала (esbuild, ts-morph, playwright) в экспорт не попали, и
  скриптов для них здесь нет.

Токены сверены с бандлом: 114 переменных `--an-*`, совпадают все.

## Раскладка

- `components/**/*.tsx` — реализация. Типов в ней почти нет: экспорт отдаёт её нестрого
  типизированной, поэтому хост компилирует её, но **не проверяет** — типы берутся из `types/`.
- `types/**/*.d.ts` — API пакета. Объявления компонентов пришли из экспорта и теперь сами
  источник правды: правка пропсов в `.tsx` без правки `.d.ts` хост не увидит.
  Объявления темы, токенов и `chart-core` сгенерированы из их (типизированных) исходников.
- `tokens/*.css`, `styles.css` — токены; `tokens/index.ts` — те же числа значениями.

Пакет исходниками, без своей сборки: `exports` отдаёт `index.ts`, и его компилирует
сборщик хоста (Vite). Хосту нужно разрешать `react` из своих `node_modules`: у панели это
`resolve.dedupe` в `vite.config.ts` и `paths` для `react` в `tsconfig.app.json`.

# Andromeda — как строить с этой системой

Библиотека компилируется в один IIFE и кладёт все 37 компонентов на `window.Andromeda`.
React берётся из `window.React` — своей копии внутри бандла нет.

```jsx
const { Button, Card, StatPair, StatusDot } = window.Andromeda;
```

## 1. Корневая обёртка и тема

Всё, что вы рисуете, должно лежать внутри узла с классом `an-root`. `tokens/base.css`
скоупит к нему **все** базовые правила, поэтому без обёртки не будет ни фона
`--an-surface-page`, ни основного шрифта, ни обводки фокуса, ни стилей ссылок:
компоненты отрисуются, но экран останется неоформленным.

Тёмная тема — атрибут `data-theme="dark"` на `an-root` или любом предке.
Светлая — состояние по умолчанию (`:root`). Руками цвета не инвертируйте:
все поверхности, текст и границы уже переопределены под этим атрибутом.

```jsx
<div className="an-root" data-theme={dark ? "dark" : undefined}>…</div>
```

## 2. Идиом: токены, а не классы

Утилитарных классов в системе **нет**. Инструментов ровно два: пропсы компонентов и
инлайновый `style` со ссылками на `var(--an-*)`. Не придумывайте своих имён классов
и своих значений цвета, отступа или радиуса — всё нужное уже есть токеном.

- **Поверхности** — `--an-surface-page`, `-card`, `-rail`, `-field`, `-input`, `-inverse`
- **Текст** — `--an-text`, `--an-text-secondary`, `--an-text-muted`, `--an-text-on-accent`
- **Акцент** — `--an-accent`, `-press`, `-soft`, `-line`, `-glow`
- **Состояния** — `--an-success`/`-soft`/`-ink`, `--an-warn`/`-soft`/`-ink`/`-border`,
  `--an-danger`/`-soft`/`-ink`/`-border`, `--an-control-knob-off` («мимо туннеля»).
  Они **не наследуют акцент и не меняются с темой** — иначе цвет перестаёт что-либо значить.
- **Границы** — `--an-border`, `--an-border-soft`, `--an-focus-ring`
- **Тип** (шорткат целиком в `font:`) — `--an-text-verdict`, `-title`, `-heading`, `-body`,
  `-body-sm`, `-caption`, `-micro`, `-code`; семейства `--an-font-sans`, `--an-font-mono`;
  насыщенность `--an-weight-regular`, `-medium`, `-semibold`
- **Ритм** — `--an-space-1`…`-10`, `-12`, `-14`; `--an-gap-inline`, `-row`, `-block`, `-section`;
  `--an-pad-row`, `-block`, `-card`; `--an-rail-width`
- **Радиусы** — `--an-radius-badge`, `-inner`, `-control`, `-block`, `-card`, `-pill`, `-dot`
- **Тени** — `--an-shadow-none`, `-hover`, `-float`, `-toast`, `-dialog`
- **Движение** — `--an-ease`, `--an-dur-hover`, `-control`, `-enter`, `-theme`, `-collapse`,
  `-pulse`, `--an-transition-hover`, `--an-transition-theme`

Три правила, которые ломаются чаще всего:

1. Между соседями — **только `gap`**, никогда `margin`.
2. Система **бордерная**: карточку от фона отделяет линия 1 px, а не тень.
   Тень есть только у пилюли, тоста и диалога.
3. Радиусы шагают по вложенности: карточка 16 → блок 12 → контрол 10 → внутренний 9 → ярлык 6.

## 3. Где лежит правда

- `styles.css` → `tokens/*.css` — все значения; читайте их, а не угадывайте.
- `components/<группа>/<Имя>.prompt.md` — как применять компонент, с примерами и запретами.
  **Прочитайте его перед первым использованием компонента**: там правила, которых нет в типах.
- `components/<группа>/<Имя>.d.ts` — контракт пропсов.
- `README.md` — тон текста, пять правил формулировок, визуальные основания.

## 4. Пример в идиоме

```jsx
const { Card, StatPair, StatusDot, Button } = window.Andromeda;

function Overview() {
  return (
    <div
      className="an-root"
      style={{
        display: "flex",
        flexDirection: "column",
        gap: "var(--an-gap-section)",
        padding: "var(--an-pad-card)",
      }}
    >
      <Card heading="Куда идёт трафик" meta="с загрузки роутера">
        <div style={{ display: "flex", alignItems: "center", gap: "var(--an-gap-inline)" }}>
          <StatusDot tone="ok" live />
          <span style={{ font: "var(--an-text-body)", color: "var(--an-text)" }}>
            vless-nl · Нидерланды
          </span>
        </div>
      </Card>

      <div style={{ display: "flex", gap: "var(--an-gap-section)" }}>
        <StatPair label="устройств в сети" value="9" />
        <StatPair label="отклик · vless-nl" value="42 мс" tone="success" />
      </div>

      <Button tone="primary">Новое правило</Button>
    </div>
  );
}
```

Текст интерфейса — сухой служебный русский: без эмодзи, без восклицательных знаков,
счётчик — это подпись и число («устройств в сети / 9»), а не фраза. Кнопка называет
действие глаголом. Полные правила — в `README.md`.

## Что где лежит (generated)

- `_ds_bundle.js` — все 37 компонентов на `window.Andromeda`.
  Первая строка — метаданные `/* @ds-bundle: … */`. React берётся из `window.React`.
- `styles.css` — единственная точка входа для стилей; только `@import` токенов.
- `_vendor/` — React и ReactDOM UMD для карточек-образцов (без CDN).
- `_preview/` — скомпилированные скрипты карточек.

### Компоненты

**analytics/** — `Bars`, `Delta`, `Figure`, `Heatmap`, `Legend`, `Lines`, `PlanMeter`, `Sparkline`, `Table`

- `Bars` — Столбцы по категориям: дни месяца, часы дня, месяцы. Стопкой — когда части складываются в целое. Наведение показывает все ряды категории и итог стопки.
- `Delta` — Изменение показателя: направление стрелкой, величина без знака, цвет — оценка.
- `Figure` — Главное число экрана — крупно, с единицей, изменением и одной строкой пояснения.
- `Heatmap` — Интенсивность по двум измерениям: день недели × час, месяц × число.
- `Legend` — Легенда графика: образец повторяет марку на графике — столбик, линию, засечку.
- `Lines` — Ряды по времени одного масштаба: факт, прогноз, препрогноз, план. Наведение показывает все ряды в точке.
- `PlanMeter` — Факт, прогноз и план в одной полосе — вместо трёх чисел, которые читатель складывает сам.
- `Sparkline` — Форма ряда рядом с числом — без осей и без подписей.
- `Table` — Таблица чисел — там, где список объектов не годится: много столбцов одинаковой природы, нужна сортировка.

**core/** — `Badge`, `Button`, `Card`, `IconButton`, `Spinner`

- `Badge` — Короткий ярлык: роль объекта или его состояние.
- `Button` — Кнопка действия: одна primary на экран, остальное — secondary/ghost.
- `Card` — Основная единица раскладки. Внутри карточки вложенные блоки идут на радиус 12.
- `IconButton` — Действие внутри строки: изменить, поднять, удалить.
- `Spinner` — Кольцо ожидания для мест без кнопки.

**data/** — `CodeBlock`, `ListRow`, `Meter`, `Skeleton`, `StatPair`, `StatusDot`

- `CodeBlock` — Текст от движка как есть.
- `ListRow` — Объект в списке: имя, пояснение, действия справа.
- `Meter` — Доля от целого.
- `Skeleton` — Первая загрузка списка.
- `StatPair` — Число с подписью — основной способ показать количество.
- `StatusDot` — Состояние одним пятном цвета.

**feedback/** — `ApplyPill`, `Callout`, `Dialog`, `Toast`, `Verdict`

- `ApplyPill` — Изменения сохраняются сразу, а в ядро уходят по этой кнопке.
- `Callout` — Находка диагностики: сколько и что именно.
- `Dialog` — Только для необратимого: снос, остановка, удаление с роутера.
- `Toast` — Сообщение о том, что действие прошло.
- `Verdict` — Ответ на главный вопрос экрана — одной из четырёх готовых строк.

**forms/** — `Checkbox`, `Chip`, `Field`, `Input`, `Radio`, `SegmentedControl`, `Select`, `Slider`, `Switch`, `Textarea`

- `Checkbox` — Множественный выбор строками.
- `Chip` — Уже выбранное значение и кнопка добавить.
- `Field` — Подпись + поле + подсказка.
- `Input` — Поле ввода; `icon` делает из него поиск.
- `Radio` — Один вариант из двух-четырёх, когда варианты надо видеть сразу.
- `SegmentedControl` — Фильтр или режим, когда вариантов два-три.
- `Select` — Список вариантов, когда их больше трёх.
- `Slider` — Параметр с границами: ползунок для быстрого движения, число рядом — для точного.
- `Switch` — Включает и выключает объект, а не «сохраняет форму».
- `Textarea` — Список записей построчно.

**navigation/** — `Breadcrumb`, `NavItem`

- `Breadcrumb` — Возврат из редактора в список.
- `NavItem` — Раздел в левом рельсе (в мобильной раскладке — пункт нижней панели).

- `guidelines/colors-state.card.html` — Состояния (Не меняются с темой и не наследуют акцент — иначе цвет перестаёт значить)
- `guidelines/colors-surfaces-dark.card.html` — Поверхности — тёмная (Тот же набор ролей: data-theme=\)
- `guidelines/colors-surfaces-light.card.html` — Поверхности — светлая (Страница, карточка, рельс, поле; карточку от фона отделяет линия, не тень)

# Andromeda — дизайн-система

Andromeda — визуальный и текстовый язык интерфейсов для **сетевых инструментов на роутере**:
плотные экраны, где числа важнее картинок, а неверное действие стоит потерянного соединения.
Впервые применён в релизе **splify2 26.9 «Andromeda»** (веб-интерфейс маршрутизации для OpenWrt/LuCI),
но не привязан к нему: ни один токен, компонент или правило текста не знает слова «splify2».

Система родилась из разбора реального продукта, а не из абстрактной палитры. Отсюда её характер:
она хорошо описывает **состояние системы, списки объектов с приоритетом и отложенное применение** —
и почти ничего не говорит про маркетинг, лендинги и картинки.

## Как подключить в код

Пакет `@andromeda/ui` (TypeScript, ESM, React 18/19 — внешняя зависимость):

```sh
npm i ../andromeda-ui            # или git-зависимость на этот репозиторий
```

```tsx
import "@andromeda/ui/styles.css";                       // токены обеих тем и акценты
import { ThemeProvider, Card, Figure, Delta, SegmentedControl } from "@andromeda/ui";

<ThemeProvider storagePrefix="myapp">                    // data-theme, data-accent на <html>
  <Card heading="Оборот сегодня">
    <Figure size="lg" value="1,40" unit="млн ₽" delta={<Delta value={-3.8} />} />
  </Card>
</ThemeProvider>
```

Сборка: `npm run build` — проверка типов, `.d.ts` из tsc, ESM-модуль для потребителей
и `ds-bundle/` для Claude Design; `npm run check` — валидатор, рендер карточек, соглашения.
Потребителю на симлинке нужен `resolve.dedupe: ["react", "react-dom"]` в Vite —
иначе на странице окажется два React.

## Content fundamentals

Тон: **сухой служебный русский**. Интерфейс не бодрится, не извиняется и не хвалит пользователя.
Он сообщает состояние и последствия. Обращение — на «вы», но почти всегда безлично:
«Список пуст», а не «Вы не добавили записи».

**Пять правил, из которых состоит весь текст.**

1. **Счётчик — подпись и число, не фраза.** `устройств в сети / 9`, в строке — `проверок с предупреждением: 1`.
   Так число не согласуется с подписью: нет склонений после числительных, а перевод — это перевод подписи.
   Запрещено: «одна проверка просит внимания», «9 устройств подключено».
2. **Вывод движка печатается дословно.** `список domains/telegram.lst старше суток` — как пришло из `diag.checks[].what`.
   Пересказ расходится с движком и требует второй формулировки того же факта.
3. **Заголовок состояния — из закрытого списка.** «Маршрутизация работает», «Есть поломки»,
   «Движок не отвечает», «Загрузка…». Ни одна строка не зависит от чисел.
   Запрещено: «Всё идёт как настроено», «Есть о чём знать» — это сочинение, а не состояние.
4. **Термин + человеческая расшифровка.** `vless-nl · Нидерланды`, `wg0 · свой WireGuard`,
   `напрямую · без туннеля`. Технический термин остаётся (он в логах и в документации), но никогда не идёт один.
5. **Объясняем только то, без чего можно сделать неверное действие.** «Нужен адрес, а не имя: движок не разрешает имена».
   Всё остальное — вычеркнуть. Абзац объяснений под полем означает, что поле спроектировано неверно.

Регистр: заголовки — как в предложении («Новое правило»), подписи и счётчики — строчными
(«устройств в сети», «записей: 84 312»), ярлыки — строчными без точки («исключение», «активно»).
Кнопка называет действие глаголом: «Остановить», «Удалить правило», «Применить» — никогда «ОК».
Эмодзи не используются нигде. Восклицательных знаков нет. Многоточие — только в состоянии ожидания
(«Применяем…», «Скачиваем…»).

Числа: русские разделители — пробел на тысячи (`84 312`), запятая на дробь (`4,2 Мбит/с`),
единицы через пробел (`42 мс`, `68,2 ГБ`). Разделитель в мета-строках — middot с пробелами (` · `).
Стрелка маршрута — `→`, стрелки трафика — `↓ ↑`.

## Visual foundations

**Характер.** Спокойная светлая или глубокая тёмная плоскость, разделённая тонкими линиями.
Никаких градиентов, стёкол, свечений и текстур. Плотность высокая — на экране много чисел, —
но воздух между блоками щедрый: 16–20 px между карточками, 8 px между строками списка.

**Цвет.** Один акцент, приходящий из темы хоста (`--sp-primary` в Argon, по умолчанию индиго `#5e72e4`),
и три фиксированных цвета состояния: зелёный `#2dce89` — работает, жёлтый `#ffc107` — предупреждение,
красный `#f5365c` — отказ. Состояния **не наследуют акцент и не меняются с темой**: если «работает»
и «отказ» перекрасить вместе с темой, цвет перестанет что-либо значить. Серый `--an-control-knob-off` —
«мимо туннеля»: не достижение и не проблема. Заливки состояний — 7–12 % прозрачности, чернила — отдельные
токены (`--an-warn-ink`), в тёмной теме светлее.

**Тип.** Onest (Latin + Cyrillic) и JetBrains Mono для данных — **вшиты и в продакшене** (`assets/fonts`,
переменные woff2, 67 КБ на четыре файла). Наследование стека LuCI давало разный интерфейс под каждой темой:
Google Sans у Argon, Helvetica у bootstrap, Times New Roman у Material. Шкала закрыта: 26/600 вердикт, 22/600 заголовок раздела, 15/600 заголовок карточки,
14/400 основной, 13/400 плотные строки и проза, 12/400 подписи, 11/400 мета. Отрицательный трекинг только
на двух крупных размерах. Моношрифт — обязателен для всего, что приходит от движка или уходит в него.

**Ритм.** База 2 px, но живут только шаги 2/4/6/8/10/12/14/16/20/22/28/40. Между сиблингами — **только `gap`**,
никогда margin: так перетаскивание, удаление и дублирование строк не ломают шаг. Рельс разделов — 236 px.
Контролы: 40 px основной, 34 px компактный, 44 px минимум на телефоне.

**Границы и слои.** Andromeda — **бордерная**, а не теневая система: карточку от фона отделяет линия 1 px
(`--an-border`), тень означает «плавает над страницей» и есть только у пилюли, тоста и диалога.
Радиусы шагают по вложенности: карточка 16 → блок 12 → контрол 10 → внутренний 9 → ярлык 6.

**Фон и изображения.** Фоновых изображений, паттернов и иллюстраций нет вовсе: единственная картинка
в интерфейсе — знак продукта. Полноэкранных фото и full-bleed блоков не бывает. Прозрачность и размытие —
только у затемнения диалога (`--an-scrim`) и залипающих шапок (`backdrop-filter: blur(8px)`).

**Состояния.** Наведение: заливка `--an-surface-field` для второстепенного, подъём на 1 px и мягкое свечение
акцентом для основного действия. Нажатие: возврат в исходное положение, без сжатия. Фокус: обводка 2 px
из акцента с отступом 2 px — видимая, потому что роутер настраивают и с клавиатуры. Выключенный объект —
50 % прозрачности **и остаётся на месте**; недоступный контрол — 55 % и `cursor: default`.

**Движение.** Одна кривая `cubic-bezier(.4,0,.2,1)`. Наведение 160 мс, переключение состояния 220 мс,
появление панели 260 мс, смена темы 280 мс, раскрытие блока 320 мс. Полосы отрисовываются от нуля
лестницей по 70 мс. Живое значение пульсирует 2,4 с. Ожидание — вращение 1 с. `prefers-reduced-motion`
гасит все длительности до 1 мс. Ничего не отскакивает и не пружинит.

## Iconography

Lucide, обводка 2 px, скруглённые концы: 16 px в контролах и строках, 18 px в рельсе, 14 px в мета-строках.
Иконка всегда сопровождает текст — самостоятельным элементом управления она бывает только в `IconButton`,
и тогда `label` обязателен. В спрайте продукта (`assets/icons-sprite.svg`) лежат бренд-глифы (bluesky и др.);
интерфейсные глифы берутся из Lucide через CDN, а в компонентах и UI kit — из `ui_kits/console/Icon.jsx`,
где нужные пути выписаны явно, чтобы страница не зависела от сети.

Эмодзи и юникод-символы как иконки запрещены. Исключение — типографские знаки в данных: `→ ↓ ↑ ×`.
Своих SVG-иллюстраций система не рисует: если нужна картинка, это либо знак, либо ничего.

## Intentional additions

Инвентарь компонентов взят из первоисточника (`ui/src/components/` и `components/ui/`). Добавлено сверх него:

- **Verdict** — заголовок состояния с закрытым списком строк. В коде продукта та же логика была размазана
  по `StatusRail`; вынесена в компонент, чтобы правило «не сочинять фразу» нельзя было обойти.
- **StatPair** — счётчик «подпись + число». Формализует правило про склонения.
- **Callout** — плашка находки со `verbatim`. Отдельный проп для дословного текста движка вместо свободного `children`.
- **Meter**, **StatusDot**, **Field** — были инлайновыми фрагментами в нескольких файлах; сведены в примитивы.

Не добавлено намеренно: Tooltip, Avatar, Tabs, Accordion, Pagination. В продукте им нет соответствия,
а вкладки внутри раздела Andromeda прямо запрещает.

### Группа `analytics/` — для панелей с числами

Добавлена при переносе на систему аналитической панели розницы (обороты, прогнозы, рейтинг продавцов):
у консоли роутера графиков не было, у панели без них нет смысла. Правила те же, что у остальной системы,
плюс одно новое — **кодировка рядов**: акцент — главный ряд (факт, продажи), серый `--an-control-knob-off` —
второстепенный, который не является достижением (выдача заказов, замороженный препрогноз), чернила `--an-text` —
план и уровни; пунктир — всё прогнозное. Токены состояния в рядах не участвуют: они остаются оценкой
(`Delta`, окраска разницы прогноз/план), иначе «зелёный» на графике перестанет что-либо значить.

- **Figure** — крупное число экрана с единицей, изменением и одной строкой пояснения; старший брат `StatPair`.
- **Delta** — изменение стрелкой и величиной без знака; цвет — оценка («лучше/хуже»), не направление.
- **PlanMeter** — факт, прогноз и план в одной полосе: заливка, пунктирная надстройка, засечка.
- **Sparkline**, **Bars**, **Lines**, **Heatmap** — графики на инлайновом SVG, одна ось, значения подписаны на марках, шкала у тепловой карты обязательна.
- **Legend** — образец повторяет марку (столбик, линия, засечка).
- **Table** — единственная таблица системы: числа вправо табличными цифрами, сортировка по заголовку, при нехватке ширины прокрутка, а не сжатие. Ранее не добавлялась, потому что в консоли ей не было применения; рейтинг из одиннадцати столбцов иначе не показать. Объекты с действиями по-прежнему `ListRow`.
- **Slider** (в `forms/`) — параметр с границами: ползунок для быстрого движения, число для точного.

## Флаги и открытые вопросы

- **Шрифт.** Файлов Google Sans нет и быть не может (лицензия), поэтому Onest — основной шрифт системы,
  вшитый в продукт (решение 2026-10: один вид под любой темой LuCI). Если у бренда есть свой шрифт с кириллицей — пришлите файлы, заменю за один проход.
- **Остаток подписки.** Блок «Подписка» на обзоре требует данных, которых нет в контракте `sub_info`
  (`ui/src/lib/rpc.ts` отдаёт url/kind/path/bytes/mtime/hwid). Нужен разбор заголовка `subscription-userinfo`
  (upload, download, total, expire); средний расход считается на стороне интерфейса.
- **Иконки.** Lucide подключается с CDN. Если в продукт нужен офлайн — скажите, соберу подмножество в спрайт.
