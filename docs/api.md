# API splify2 для приложений

Приложения вне LuCI — splify2 для компьютера, скрипты, свои панели — управляют splify2 через HTTP:
`http://<роутер>/cgi-bin/splify2-api/v1/…`. Внутри это те же методы объекта `splify2`, что зовёт
страница LuCI ([контракт объекта](rpcd-api.md)): набор методов, их вход и выход совпадают.

Отличие от `/ubus` — вход. Сессия ubus ограничена сроком (по умолчанию пять минут без обращений) и
пропадает с перезагрузкой роутера, и приложению пришлось бы снова и снова спрашивать пароль. Здесь
пароль нужен один раз — при подключении устройства, — а дальше устройство живёт на паре токенов.

Шлюз ставится вместе с пакетом `luci-app-splify2` (в выпусках после 26.10.3), отдельно настраивать
ничего не нужно.
Нужен ucode с модулями `fs` и `ubus` — пакет тянет их зависимостями.

## Токены

| Токен | Вид | Срок | Где живёт на роутере |
|---|---|---|---|
| доступа | `sa_` + 64 шестнадцатеричных знака | 1 час | в памяти (`/tmp/splify2-api/access`) |
| обновления | `sr_<устройство>.<секрет>` | пока устройство пользуется им хотя бы раз в 90 дней | хешем SHA-256 в `/etc/splify2/api/devices` |

- Токен доступа идёт в заголовке `Authorization: Bearer sa_…` каждого вызова.
- Токен обновления меняется при **каждом** обновлении: ответ несёт новую пару, прежний токен
  обновления годен ещё 60 секунд (на случай, если ответ потерялся в сети). Предъявленный позже —
  признак кражи: устройство отключается целиком.
- После перезагрузки роутера токенов доступа нет (они в памяти): вызов получает `401`, приложение
  обновляет пару и повторяет вызов. Устройства переживают и перезагрузку, и обновление прошивки
  (`/etc/splify2/api/` записан в `/lib/upgrade/keep.d/splify2`).
- Подключить устройство может только учётная запись rpcd с правом записи на `splify2` (как у root).
  Учётной записи только для чтения шлюз отвечает `403 forbidden`.
- Пять неверных паролей с одного адреса за пять минут — пауза для этого адреса до конца окна
  (`429`, поле `retry_after` в секундах).

## Адреса

Все ответы — JSON. Ошибка — HTTP-статус и `{"error": "<код>", "message": "<текст для человека>"}`.

### `GET /v1/info`

Без токена. Что за роутер и какая версия API.

```json
{ "product": "splify2", "api": 1, "version": "<версия пакета>", "hostname": "OpenWrt", "auth": ["password"] }
```

### `POST /v1/auth/login`

Подключить устройство. Тело:

```json
{ "username": "root", "password": "…", "device_name": "Рабочий ноутбук", "platform": "win32" }
```

`username` можно не указывать (`root`), `device_name` — обязательно, до 64 знаков. Ответ:

```json
{
  "access_token": "sa_…", "token_type": "Bearer", "expires_in": 3600,
  "refresh_token": "sr_6c048319a868e045.…",
  "device": { "id": "6c048319a868e045", "name": "Рабочий ноутбук" }
}
```

Ошибки: `401 bad_password`, `403 forbidden`, `429 too_many_attempts`, `400 bad_request`.

### `POST /v1/auth/refresh`

Новая пара токенов. Тело — `{"refresh_token": "sr_…"}`, ответ — как у входа. Ошибки — `401`:
`bad_token` (токен не подходит), `revoked` (устройство отключено, долго не подключалось или токен
предъявлен повторно). После `revoked` нужно подключиться заново.

### `POST /v1/auth/logout`

С токеном доступа. Отключить своё устройство: роутер забывает его токены.

### `GET /v1/devices`

С токеном доступа. Подключённые устройства: `id`, `name`, `platform`, `created`, `seen` (время
последнего обновления токена), `ip`, `current` (это устройство).

### `POST /v1/devices/<id>/revoke`

С токеном доступа. Отключить устройство: его токены перестают действовать сразу, и следующий его
вызов получает `401 revoked`.

### `POST /v1/call/<метод>`

С токеном доступа. Вызов метода объекта `splify2`; тело — аргументы метода объектом JSON (пусто —
без аргументов), ответ — ответ метода как есть ([контракт объекта](rpcd-api.md)).

```sh
curl -H 'Authorization: Bearer sa_…' -d '{"address":"youtube.com"}' \
     http://192.168.1.1/cgi-bin/splify2-api/v1/call/explain
```

Ошибки: `404 no_method`, `400 bad_args`, `504 timeout`, `502 backend_error` (текст ubus в
`message`).

### Долгие вызовы: `?async=1` и `GET /v1/jobs/<id>`

uhttpd обрывает обработчик ровно через минуту (`script_timeout`), а установка пакета или
скачивание списков бывает дольше. Такие вызовы шлют с `?async=1`: шлюз ждёт ответа до 45 секунд,
не дождался — отвечает `202 {"job": "<id>", "poll": "/v1/jobs/<id>"}`. По этому адресу (с тем же
токеном) ответ дочитывается: снова ждёт до 45 секунд и отдаёт либо ответ метода, либо снова `202`.
Ответ задания отдаётся один раз; неспрошенные задания старше 10 минут стираются при следующем задании.

Без `?async=1` вызов идёт напрямую и стоит столько же, сколько у страницы LuCI; дольше минуты он
не проживёт — как и у неё.

splify2 для компьютера шлёт с `?async=1` методы `apply`, `steer_install`, `splify2_install`,
`steer_module_add`, `steer_module_del`, `list_fetch`, `lists_update`, `sub_set`, `sub_refresh`,
`backup_put`.

## HTTPS

Шлюз отвечает и по `https://`, если на роутере стоит сертификат uhttpd (пакет `luci-ssl`), но
сертификат там самоподписанный. splify2 для компьютера пока подключается по `http://` — как
страница LuCI в домашней сети.
